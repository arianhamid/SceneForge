# ۹. واژه‌نامه انگلیسی به فارسی

این واژه‌نامه معادل فارسیِ [`docs/GLOSSARY.md`](../GLOSSARY.md) اصلی است، با توضیح بیشتر. در کد و مستندات انگلیسی، همیشه از نام انگلیسی استفاده کن — این‌جا فقط برای فهمیدن معنا است.

## مفاهیم پایه

**Media (رسانه)** — نماینده‌ی یک فایل ورودی (تصویر، ویدیو، صدا). غیرقابل‌تغییر. اطلاعاتش با `evolve()` اصلاح می‌شود، نه با تغییر مستقیم.

**Artifact (آرتیفکت / مصنوع)** — یک مشاهده‌ی خام و غیرقابل‌تغییر که یک Provider از روی Media استخراج کرده. مثال: یک برش صحنه، یک قاب، یک تکه متن گفتاری.

**Provider (پرووایدر / ارائه‌دهنده)** — چیزی که Media می‌گیرد و Artifact تولید می‌کند. پیاده‌سازی یک یا چند Capability.

**Capability (قابلیت)** — نام یک نوع کار (مثل `TRANSCRIBE`، `FACE_DETECTION`) که کد به آن وابسته است، نه به یک مدل خاص.

**Pipeline (پایپ‌لاین)** — هماهنگ‌کننده‌ی اجرای یک Provider روی یک Media: غنی‌سازی، بررسی سازگاری، بررسی کش، اجرا، ذخیره‌ی کش.

**MediaEnricher (غنی‌ساز رسانه)** — چیزی که اطلاعات جایگزین (placeholder) در Media را با اطلاعات واقعی جایگزین می‌کند (مثلاً مدت‌زمان واقعی ویدیو).

**ArtifactStore (انبار آرتیفکت)** — محل ذخیره‌ی کش برای نتیجه‌ی Provider ها، بر اساس هویت Media + نام Provider + نسخه.

## لایه‌ی دانش

**Entity (موجودیت)** — معادل Artifact در لایه‌ی دانش؛ نتیجه‌ی ترکیب چند Artifact توسط یک KnowledgeBuilder.

**KnowledgeBuilder (سازنده‌ی دانش)** — چیزی که Artifact ها را می‌گیرد و Entity تولید می‌کند (`build()`).

**RelationshipBuilder (سازنده‌ی رابطه)** — چیزی که Entity ها را می‌گیرد و Entity جدید (رابطه یا ادغام) تولید می‌کند (`relate()`).

**EntityStore (انبار موجودیت)** — محل ذخیره‌ی کش برای Entity ها، مشابه ArtifactStore اما با کلید متفاوت (بر اساس مجموعه‌ی ورودی‌ها + نام سازنده).

**Knowledge Graph (گراف دانش)** — مجموعه‌ی کامل Entity ها و روابط بین‌شان. در این پروژه هنوز یک کلاس اختصاصی ندارد؛ فقط EntityStore + توابع پیمایش ساده است.

## اصطلاحات معماری

**Provenance (منشأ / سرچشمه)** — این‌که یک Entity بداند چرا (توسط کدام سازنده، از روی کدام Artifact ها، با چه میزان اطمینان) ساخته شده.

**Immutable (غیرقابل‌تغییر)** — چیزی که بعد از ساخته‌شدن نمی‌توان مقادیرش را تغییر داد؛ فقط می‌توان نسخه‌ی جدیدش را ساخت.

**Parents (والدین)** — فیلدی روی Artifact/Entity که شناسه‌ی چیزهایی را نگه می‌دارد که این یکی از روی آن‌ها ساخته شده.

**Protocol (قرارداد ساختاری)** — تعریف پایتونی که می‌گوید «هر کلاسی با این متدها، از این نوع محسوب می‌شود»، بدون نیاز به وراثت صریح.

**Dependency Injection (تزریق وابستگی)** — دادن یک وابستگی (مثل یک مدل) از بیرون به یک کلاس، به‌جای این‌که خودِ کلاس آن را بسازد. باعث تست‌پذیری بهتر می‌شود.

**Capability Registry (رجیستری قابلیت)** — نگاشتی که مشخص می‌کند هر Capability با کدام نوع‌های Media سازگار است.

**Cache Key (کلید کش)** — رشته‌ای یکتا که از ترکیب هویت ورودی + نام/نسخه‌ی پردازش‌کننده ساخته می‌شود، برای تشخیص «آیا این دقیقاً قبلاً محاسبه شده یا نه».

## اصطلاحات فرآیند توسعه

**ADR (سند تصمیم معماری / Architecture Decision Record)** — سندی که یک تصمیم مهم معماری، دلیلش، و جایگزین‌های بررسی‌شده را ثبت می‌کند.

**Spike (اسپایک / آزمایش اکتشافی)** — نوشتن کد واقعی برای پاسخ به یک سؤال معماری، به‌جای حدس‌زدن یا طراحی روی کاغذ.

**Sprint (اسپرینت)** — یک دوره‌ی کاری با یک هدف مشخص (در این پروژه، هر اسپرینت یک ADR یا مجموعه‌ای مرتبط تولید کرده).

**Cross-domain (میان‌حوزه‌ای)** — وقتی یک سازنده‌ی دانش، اطلاعات از دو قابلیت متفاوت (مثلاً ساختار ویدیو + تشخیص تصویر) را با هم ترکیب می‌کند.

## کلمات نسبتاً مبهم که ارزش توضیح دارند

**Evidence (شواهد)** — در سند «مدل جهان»، معادل Artifact — چیزی که مستقیماً قابل‌مشاهده است، بدون تفسیر.

**Fact (حقیقت)** — سطحی بالاتر از شواهد؛ گزاره‌ای عینی و ساخته‌شده از شواهد (مثلاً «در باز شد»). هنوز در پروژه پیاده‌سازی نشده.

**World Model (مدل جهان)** — چشم‌اندازی برای یک شیء مرکزی که همه‌ی دانش یک فیلم را نگه می‌دارد. تا امروز به‌عنوان یک مفهوم پذیرفته شده، اما به‌صورت کد ساخته نشده — چون `EntityStore` معمولی تا الان کافی بوده.
